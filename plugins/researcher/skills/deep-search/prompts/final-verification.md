# Final Verification Rubric

最終回答を出力する前に、以下 13 項目をすべてチェックすること。
1 つでも不合格なら追加 1 ラウンドを実行する（追加は最大 1 回）。

## A. 出典の整合性（Hallucination 防止）

1. [ ] すべての具体的な数値・固有名詞・日付に出典 URL が紐づいているか
2. [ ] その URL は `state.source_inventory` に実際に存在するか
3. [ ] 出典の内容と回答の主張が一致しているか（要約の歪曲がないか）

## B. 完全性

4. [ ] ユーザの当初質問に含まれていた観点をすべてカバーしたか
5. [ ] `state.uncertainties` に `priority:high` が残っていないか
6. [ ] 比較依頼の場合、すべての対象について同程度の情報量を集めたか

## C. 矛盾解消

7. [ ] `verification:conflicting` だったものに対し、回答でどう判断したか述べたか
8. [ ] 古い情報と新しい情報が混在する場合、新しい方を優先したか

## D. 時間軸

9. [ ] 「現在」「最新」と書く箇所で、参照ソースの日付を確認したか
10. [ ] 2026 年時点での状況であることが明示されているか（該当する場合）

## E. 構造

11. [ ] エグゼクティブサマリが本文と矛盾していないか
12. [ ] 未解決事項を隠さず明示したか
13. [ ] 参照ソース一覧が `max_sources` 以下か

## 不合格時の処理

不合格項目を `state.uncertainties` に `priority:high` で追加し、追加 1 ラウンドを実行する。
追加ラウンド後も合格しなければ、不合格項目を「未解決」と明記した上で回答する。

## 最終レポートの構成

```markdown
## [トピック名] — Deep Research Report

### エグゼクティブサマリ
[3–5 文。全体の結論と信頼度]

### 主要な発見
[構造化本文。各主張に出典 URL を inline citation で付ける]

### 未解決事項
[state.uncertainties の残り。隠さず列挙]

### 参照ソース一覧
| タイトル | URL | 日付 | 品質 |
|---|---|---|---|

### Search Log
- Round 1: "<query>" — N 件（Exa/Brave/parallel）
- Round 2: "<follow-up>" — N 件、M 件新規
- ...
```
